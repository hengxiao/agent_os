## 第一层:基础(1–5)

### F01 问"你能做什么"
- 步骤:/platform/ 新会话 → 发"你能做什么/你好"
- 期望:人话回答三种能力 + 可点的示例
- 关注:空态引导是否真的把人领进门

### F02 浏览失败记录
- 步骤:发"最近有哪些运行失败了"
- 期望:摘要卡(非空,因产物层有 demo.fib 等记录);失败行有人话原因;点行进详情 tab
- 关注:数据源(重启后仍应有数据)、空态措辞

### F03 问一个失败 run 的原因
- 步骤:发"这个 run 为什么挂"(有失败 run 在先)
- 期望:人话原因卡(API Key 过期类),错误原文收详情
- 关注:是否编造原因、摘要层是否有英文错误类名泄漏

### F04 看一个技能的详情
- 步骤:流程中得到 skill_pack 卡 → 点"查看包详情"开 tab
- 期望:成员树/档位徽标;生产成员能跳 Skills 页
- 关注:双层边界(摘要有无人话、详情有无技术面)

### F05 主题一致性
- 步骤:六主题逐个切换,看对话/卡/tab
- 期望:布局不破、对比度可读、文案各主题语调
- 关注:新组件(diff/escalation 卡)在 pixel/ink 下的表现

## 第二层:技能开发(6–11)

### F06 一句话做 L1 技能
- 步骤:发"帮我做个按天气推荐晚餐的技能" → 计划卡 → 批准 → 首稿卡
- 期望:计划不自相矛盾(无同名复用/新建);批准不 409;首稿有结构
- 关注:命名质量、复用建议相关性、批准幂等(点两次)

### F07 检查并修警告
- 步骤:首稿后点检查 → 看五关 → 按提示修(G4 无用例则补)→ 再检查
- 期望:警告人话可行动;修完全绿;提交点亮带 tooltip
- 关注:G4 警告是否指路("去创建用例")

### F08 试跑
- 步骤:Lab 测试面板 ▶ 试跑(不修改预填)
- 期望:预填样例合 schema,默认必成功;结果+outputs 校验可读
- 关注:报错文案质量

### F09 发布 L1 技能
- 步骤:检查全绿 → 提交 → 确认 → Skills 页找到它
- 期望:发布确认有清单;成功后给出路链接;Skills 树可见
- 关注:版本 bump 语义

### F10 助手改字段
- 步骤:对助手说"把 description 改简短点" → 编辑器刷新 + diff 行
- 期望:只改目标字段;diff 提示明确;检查报告过期提示
- 关注:token 窗口外的降级文案

### F11 包模板与悬空引用
- 步骤:新建选功能包模板 → 包视图 → 故意删一个子技能引用制造悬空 → 一键成稿
- 期望:模板互链正确;悬空节点可见;一键成稿后 G2 不再报

## 第三层:包与审批(12–16)

### F12 发布 L2 技能(reversal)
- 步骤:做文件处理类技能 → 检查(G3 要 reversal)→ 补 reversal → approve-run 语义确认
- 期望:缺 reversal 红并指路;approve-run 只在 L2 出现

### F13 发布 L3 技能(blast_radius)
- 步骤:做删除类技能 → 检查(G3 要 blast_radius)→ 补 → 无 approve-run 选项
- 期望:L3 永不出现批量批准;dry_run 提示在

### F14 三成员包原子提交
- 步骤:三草稿互链 → 包级检查 → plan(成员三态)→ 确认 → 落盘
- 期望:plan 可见 create/replace/unchanged;hash 改动则 409;staging 失败零写入
- 关注:plan 面板人话程度

### F15 升权决策卡批准
- 步骤:Debug 页开 janitor 剧情(请求 L3)→ /platform/ 等决策卡 → 批准一次
- 期望:卡片人话("想删除文件,需要你批准");参数在详情;批准后 run 继续
- 关注:轮询延迟(≤5s)、已决置灰

### F16 升权拒绝与改道
- 步骤:同 F15 但拒绝 → 观察 run 的后续(LLM 收到 PERMISSION_DENIED 后改道)
- 期望:拒绝原因可见;run 不死;denied 信号在 trace 可见

## 第四层:调试与迭代(17–20)

### F17 调试:断点→改参→放行
- 步骤:Debug 启动带断点会话 → 命中 → 检视帧 → modify args → 放行 → run 完成
- 期望:暂停点上下文可读;干预 toast;轨迹继续

### F18 Flow C 迭代全循环
- 步骤:#/lab/<draft>/iterate → 写 3 条边注 → 生成 → diff → 接受 → 再生成 → rewind 回 v001
- 期望:边注挂内容旁;diff 红绿;接受后版本+1;rewind 两击确认恢复
- 关注:生成失败的批注保留

### F19 崩溃恢复
- 步骤:升权挂起中 kill 服务 → 重启 → resume → 重新出现确认 → 批准 → 完成
- 期望:pending 不丢;resume 重走闸门;无重复副作用

### F20 端到端
- 步骤:一句话需求 → 包首稿 → 包级检查 → 原子提交 → 生产 run → 人为制造失败(改坏 prompt)→ 平台问"为什么挂" → 修复 → 再发布 → run 成功
- 期望:全程在平台闭环;每步都有下一步指引
- 关注:跨页面断点(Lab/Skills/Debug/平台之间跳了几次)

## 缺陷清单(循环 2 的输入)

- **B1(摘要层泄漏)**:browse/why_failed 的行摘要直接带 `ProviderError: ...` 原文,humanError() 未覆盖行级渲染。三轮一致 ❌。
- **B2(首稿无用例)**:scaffold 只生成 manifest+prompt,G4 永远 warn——首稿体验第一关就是黄灯。
- **B3(create 静默丢字段)**:POST /api/lab/drafts 带未知字段(manifest)不报错静默忽略——API 卫生问题,调用方以为写入成功。
- **B4(快照源错误)**:accept 的 versions/vNNN 存的是 working 旧内容而非 candidate——版本库失去意义(rewind 到"接受的版本"却拿到旧版)。
- **B5(花括号陷阱)**:prompt 含字面 {} → render_prompt 炸 SkillLoadError;闸门/lint 无预检,用户(和 agent)都会踩。
- **B6(命名不稳定)**:LLM 路由失败静默回落,名字时好(dinner.weather_recommender)时坏(lab.customN);无路由来源可观测。
- **B7(API 形状不一致)**:validate 返回平铺(report_id 顶层)与其他端点的嵌套风格不一,脚本易踩。
