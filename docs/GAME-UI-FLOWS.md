# 信件版使用流定义(Game UI Flows)

> 版本:v0.1(流程定义稿)
> 对象:Godot 信件宿主(`godot/apps/doc_editor/letter/`)的全部用户流
> 关系:形态设计见 `docs/GAME-UI-DOC.md`(信纸/便签/版本轴);后端契约基准见
>   `docs/PLAN-ANNOTATION-WORKFLOW-V2.md`(annotations 模型/generate/reanchor)
>   与 `docs/DOC-EDITOR.md`;本文定义**每个用户行为对应的系统流程、用户所见、
>   进度表达、状态可知性**。
> 标注约定:`[已落地]` = Godot 侧已实现并验证;`[定义]` = 本文定义的目标行为
>   (差距清单见 §10);`[后端]` = 既有端点语义,视图层只消费。

## 0.1 核心循环:UI 围绕它组织(v1.6 裁决,2026-08-17)

> **v1.8 形态更替(2026-08-20)**:三站循环轨道(LoopTrack)已退役——闭环
> 思想(检查→注释→再生成)不变,组织形态改为**版本页栈置顶 + 右侧双主钮**
> (再生成 = ③站主操作;版本树 = 全局回溯面;评审回印钮栏)。详见 §6 与
> 文末 v1.8 施工注;本节以下保留为闭环思想的原始裁决记录。

**检查 → 注释 → 再生成**是本产品的闭环。功能罗列(一排印钮)违反最基本的
UI 原则——界面必须回答"我在循环哪一步、下一步干什么"。游戏里的现成解法是
**任务追踪器**,本文采纳为组织原则:

```
   ① 检查 ──── ② 注释( N )──── ③ 生成
    ↑____________________________│(环闭合 → 回流动画)
```

1. **循环轨道置顶**:三站点;当前站 live 点亮;②站挂 pending 计数徽标(计数
   = 燃料表);③站在 N>0 时才激活(主操作态)。
2. **每站一个主操作**:①「编者先读」(评审);② 隐式(右键写批注,轨道提示
   "再写一条,或去生成");③「生成下一版」。次行动作(保存/快照/回溯/导出)
   退居印钮栏,不与主操作争视觉。
3. **站点可点 = 主操作**:点① = 评审;点③ = 生成。轨道不是装饰条,是主行动面。
4. **环闭合可见**:生成成功 → 亮点从③流回①(回流动画)+ 新版本落案 +
   变化段晕染 + 批注变绿 pop——玩家**看见**环闭上了,这是闭环反馈。
5. **引导非牢笼**:轨道给"下一步该干什么"的暗示,不锁行为(任何动作仍可直达)。
6. 阶段条(起草/封存/回标)归属③站——长任务的可读阶段挂在它的主站上。

**状态机**:`check → annotate → generate → check`。
- 打开文档 / 回溯完成 / 生成成功 → check;
- pending 批注 0→N → annotate(自动前移);
- 生成进行中 → generate(busy 站点脉动);
- 全终态且无 pending → 回 check。

## 0. 总则:进度与可知性六原则

一切流的公共纪律(全部继承既有设计,不是新要求):

1. **状态双编码**:颜色永远有文字/图标伴随(WEB-A11Y 的机检纪律);动效是强调,
   不是唯一信息通道(reduced-motion 降级后状态仍可读)。
2. **状态栏是不动点**:任何流进行中/刚结束,状态栏有一句人话("正在起草新稿…"
   /"已生成 v008 · 采纳 1 / 忽略 0")——黑话不上屏(禁忌词纪律:版本号/锚点/
   端点名不进这句话,细节进各面)。
3. **长任务用具名阶段,不用假百分比**:LLM 动作(生成/评审/回执联)一律拆成
   可读阶段条(如:读批注 → 起草 → 封存 → 回标),当前阶段点亮;没有进度数字
   可编,**就不编**。
4. **改变世界的动作必有人按**:誊回/盖印回溯/生成,都是人发起、人确认;
   两段确认只用于不可轻悔的动作(回溯;生成是新页不是覆盖,单段即可)。
5. **失败不静默**:原位报错 + 可重试入口;LLM 故障一律有降级面(回落规则/
   原始数据),503 归类与后端一致。
6. **每个动作有回声**:动作成功的标志 = 一个具名动效(盖章/晕染/飞入)+ 状态栏
   一句话;失败 = 无动效 + 错误说明。动画只随成功播放(先管道,后盖章)。

### 通用构件(进度词汇表)

| 构件 | 语义 | 规格 |
|---|---|---|
| 印钮五态 | idle(可用)/ disabled(无对象,如版本空时回溯)/ busy(执行中,置灰)/ ok(盖章回声)/ fail(红,文案换"重试") | 与 DOM 版生成钮四态(PLAN-V2 P3)同构,busy 期间同钮拒重入 |
| 状态栏人话行 | 系统正在/刚做完什么 | 一句话,人话;伴随色点(live 进行中 / ok 成功 / danger 失败) |
| 阶段条 | LLM 长任务的可读阶段 | 横排阶段名,当前阶段 live 点亮 + 已过阶段 ok 打勾;挂在动作发起处 |
| 具名动效 | 成功回声/变化标记 | stamp-press / text-reveal / change-flash / note-arrive / page-fan(MotionPlayer 档位,主题决定强弱) |
| 空态/引导 | 无对象时的下一句话 | 三句以内,告诉用户下一步能干什么(如"还没有批注,右键段落写一条") |

## 1. 读信(打开文档) `[已落地]`

- **触发**:信箱列表点一封 / 新建一封。
- **系统流程**:`GET docs/{name}` + `bubbles` + `annotations` 三路读 → spawn
  `kind=doc`(action 管道锚)→ 信纸落案。
- **用户所见**:信纸文字逐段晕染入场(text-reveal);版本印(页角朱砂 vNNN);
  有批注的段落行文末挂 `[注×N]`。
- **进度表达**:打开中状态栏"打开 X …";三路读是亚秒级,不做进度面。
- **可知性**:状态栏"已打开 X(instance …)";顶栏连接点(live=在线/warn=断)。
- **失败**:后端不可达 → 状态栏红字 + 引导"先用 run-web.sh 起服务";文档不存在
  → 404 归类为一句人话,信箱列表不变。

## 2. 写批注(右键段落 → 批注坞) `[已落地]`

- **触发**:段落上右键(或点行文末既有 `[注×N]` 标记)。
- **系统流程**:开批注坞 → 用户写 → `存批注` → `POST /annotations`(upsert,
  状态 pending)→ 重拉批注 → 标记刷新。删除 = `bubbles/delete`(幂等)。
- **用户所见**:坞内自上而下:锚段摘录(斜体)→ 状态章 → 批注输入框 →
  存/删;行文末 `[注×N]` 即时出现/计数变化。
- **进度表达**:存取是亚秒级;按钮点击即状态栏"已存"。
- **可知性**:状态章明说生命周期:● 新批注 / ● 待批处理(pending)/
  ● 已誊回(applied)/ ● 已忽略(ignored)/ ● 已过时(outdated)——状态即教育。
- **确认点**:无(批注不改世界,只是攒意见;改动永远走生成/回执联)。
- **失败**:保存失败 → 状态栏红字,坞内草稿保留不丢;锚点越界(文档已变)
  → 标记不再挂段,批注仍在库(与 web"挂空不建泡"同语义)。

## 3. 批注式生成修改(攒批注 → 生成 → 新版本) `[接口已通;阶段条为定义目标]`

**这是核心流**。用户在若干段落留了批注(pending),点顶栏「再生成(N)」。

### 3.1 系统流程 `[后端]`

`POST /docs/{name}/generate`:全部 pending 批注 + 回执联上下文 → LLM 一次生成
完整新稿(XML 块契约,解析不合重试一次,再败 502 **不半截落库**)→ 工作稿更新
+ **自动封存新版本**(meta 带 generationInput/annotationResults)→ 批注逐条
标 applied/ignored + aiNote → reanchor(精确 → ±3 行模糊 → outdated);
baseVersion 与最新快照不符 → 409。

### 3.2 用户所见与进度(目标态)

| 阶段 | 信纸/印钮 | 状态栏(人话) |
|---|---|---|
| 0 发起 | 「生成」钮转 busy(置灰,计数徽标 = pending 数) | "读批注 N 条…" |
| 1 起草 `[定义]` | 阶段条:读批注 ✓ → **起草中**(live 点亮) | "编者在起草新稿(约 30–90 秒)…" |
| 2 封存 `[定义]` | 阶段条:起草 ✓ → **封存** | "新稿封存为 vNNN …" |
| 3 回标 `[定义]` | 批注章变色(pending→applied 绿/ignored 灰),变化段墨晕扩散(change-flash) | "已生成 vNNN · 采纳 N / 忽略 M" |
| 4 回声 | 盖章(stamp-press)+ 新稿文字晕染(text-reveal) | 随后空隐 |

- **成功入口语义**:新版本落叠 ≠ 自动采纳视角——信纸显示的就是新工作稿
  (生成即写工作稿,`[后端]` 语义);用户想对照 = 页栈展开旧版看摘要。
- **拒绝半截**:502/503 时信纸原样,无任何半成品落库 `[后端]`。

### 3.3 可知性

- 全程状态栏有人话阶段;印钮 busy 期间不可重复点(防双击双胞胎);
- 无 pending 时「生成」置灰 + tooltip"先右键段落写批注"(死路预防);
- 完成后批注章就是结果面:绿 = 已誊回(悬停/点开可见 aiNote 说改了什么),
  灰 = 已忽略(aiNote 说为什么),橙虚线 = outdated(原文找不回了)。

### 3.4 确认点

单段(点「再生成」即发起)——生成产生**新页**,不改历史,旧版永远在页栈
(与版本树)里,可回溯;不是不可逆动作,不配两段。

### 3.5 失败与降级

| 失败 | 表现 | 出口 |
|---|---|---|
| LLM 装配/执行故障(503) | 印钮转 fail 红"重试";状态栏"编者暂不可用:…" | 点重试再走;批注仍 pending 不丢 |
| 解析不合(502) | 同上,"新稿不合格式,未落库" | 重试 |
| baseVersion 冲突(409) `[定义]` | 状态栏"版本已变化,先看最新版";自动重拉文档 | 重拉后再生成 |
| 无 pending | 钮 disabled | 引导写批注 |

### 3.6 完成后状态

`annotations` 全部终态化(pending 清零或留未回条);`versions` 头插新版;
信纸 = 新工作稿;`[注×N]` 按终态着色 `[定义]`;状态栏摘要顶替,下一次输入清。

## 4. 回执联对话修改(chat) `[已落地]`

- **触发**:信末回执联输入需求("把标题改成 X"/"按批注改一遍")→ 寄出。
- **系统流程**:`POST /chat` → doc_editor(白名单 = 本文档 doc.read/doc.edit)
  直接改全文 → **changed = 服务端全文对比**(不信技能自报)→ 双侧消息落 chat.json。
- **用户所见**:回执联上用户条 + 编者回复;changed=true → 信纸自动重载,
  变化段墨晕。
- **进度**:寄出即状态栏"寄出,编者处理中…";回复到达替换为摘要/"文档已更新"。
- **可知性**:回复文本即状态;死路预防 `[后端]`:无批注却说"按批注改" →
  直接回引导("先在有意见的段落上右键留一条批注"),不起 run、不编造。
- **失败**:503 → 状态栏"编辑助手暂不可用";输入不丢。
- **边界**(沿用 D5 裁决):chat 是生产面(即时改),批注是攒意见——两条路并存,
  不互相打断。

## 5. 保存 + 快照(盖章) `[已落地]`

- **保存**:信纸内容(面板模式可手改)→ `doc.save` 管道 → 成功盖章 + "已保存";
  dirty 态 = 状态点 warn 黄 + "未保存"字样(双编码)。
- **快照**:当前工作稿封存为 vNNN(版本印即时换新号)→ 盖章回声。
  快照不改内容,只是"压一页进叠"。
- **进度**:亚秒级,无进度面;按钮点下即状态栏回声。
- **失败**:400/500 → 红字原因(如 schema 不合),内容保留。

## 6. 回溯(版本页栈 + 版本树) `[已落地;v1.8 取代时间卷轴]`

- **触发**:顶栏即页栈(常开,不用点);顶栏右「版本树」钮 = 分支覆盖层。
- **版本页栈**(顶栏主件):从当前版回推 ≤20 版,一版一枚小页面,左新右旧
  部分重叠成叠;悬停 = **翻书展开**(抬高放大 1.35 + 详情卡:时间/来源/
  对当前祖版的 LLM 一句话摘要(difsum 缓存,命中即回)+「回到这版」)。
- **版本树覆盖层**:parent 链画成分支图——**回推线性**(每节点沿 parent
  上溯),**前衍可分支**(同 parent 多个子代同层排开);点节点 = 选中该版
  (关层 + 页栈展开对应页);点空白/Esc = 收拢;链长首屏放不下时拖拽平移
  (技能树式,钳制防拖丢)。
- **树状版本模型(v1.8 后端)**:回到旧版 → 写批注 → 再生成,新版**挂在
  旧版下面**成新分支(工作稿记 baseVersion,snapshot/generate 缺省以其为
  parent);任何版本往回推历史仍是线性的。
- **盖印回溯**:首击 = 预持(钮变"确认回到 vNNN?");再击 = `doc.rewind`
  管道(历史不动,废弃版标 rolledBackTo)→ 新稿落案 + 文字晕染;
  状态栏"已回滚到 vNNN(历史不动)"。
- **可知性**:摘要就是"回到这版意味着什么"的事前说明;两击是唯一的确认点
  (改工作副本,谨慎动作配两段);当前祖版无回溯钮(回自己无意义)。
- **失败**:版本不存在(404)→ 状态栏人话;摘要故障 → 降级红绿行;
  点空白/Esc = 收拢不动作。

## 7. 评审(批注雨) `[已落地]`

- **触发**:印钮「评审」→ `POST /review`(LLM 通读全文)。
- **系统流程**:doc_reviewer(tools=[] 只读)→ 锚点批注集 → 校验(锚点格式 +
  severity 白名单,不合条丢弃)→ 落库 + 挂段。
- **用户所见**:各段行文末 `[注×N]` 依次出现(note-arrive 飞入);状态栏
  "评审完成:批注已挂到各段"。
- **进度**:评审中 = 印钮 busy + 状态栏"评审中…(通读全文)"。
- **可知性**:批注章带 severity 语义(must/should/nit);越界锚点挂空不建签
  (与后端同语义)。
- **失败**:503 → 红字"评审助手暂不可用";不落半截。

## 8. 导出 `[已落地]`

- **触发**:印钮「导出」→ 全文复制到系统剪贴板,状态栏"已复制全文(N 字)"。
- **留口**:另存 .md 对话框(宿主能力已在,未接钮)。
