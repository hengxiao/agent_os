## 1. 核心隐喻:文档是一封信,不是一页滚动的 DOM

游戏早就解决了"让人愿意读大段文字"的问题,手法是**把文字变成物件**:

| 游戏机制 | 出处例子 | 它做对了什么 |
|---|---|---|
| 信箱 | 动森/星露谷/原神邮件 | 信是实体:信封、火漆印。"信到了"是事件,有期待感 |
| 信件/书籍 | 巫师3/老滚 | 居中一页纸、背景压暗、衬线字、翻页——注意力被强制收拢 |
| 任务日志 | 各类 RPG | 左列条目带状态章;完成 = 盖章;"追踪中"置顶 |
| 视觉小说 | AVG | 文字渐变出现,阅读有节奏 |

映射到 Doc Editor(与 web 版的结构一一对应,不新造数据):

| 既有概念 | 信件模型 | 说明 |
|---|---|---|
| 文档列表 | **信箱** | 每封信一行:信封图标 + 标题 + 首行 + 时间;未读(有新批注)= 信口翘起 + 光点 |
| 文档 | **一页信纸** | 居中、暖白纸色、背景压暗;一次只读一封信 |
| 段落块(MdBlocks) | 信纸行文 | 当前段 = 左侧一道微光(不是灰底选中框) |
| 批注(bubbles) | **页边便签(眉批)** | 钉在信纸右缘,一根细线牵到锚点段;收起 = 小折签 + 计数;展开 = 完整对话便签 |
| 未读 | 便签翘起 + 呼吸光点 | 沿用 badge 记账语义 |
| 版本 | **信纸叠** | 每版一页,页角盖版本朱砂印(v001…);**历史不动** = 旧页永远压在下面 |
| 保存/快照 | **盖章** | 朱砂印砸落 + 纸面微震(ink 主题的印章意象物化) |
| 回溯(rewind) | 整叠扇形展开,抽一页压到最上 | 版本不可变:抽出的只是"临幕",工作稿永远在最上 |
| 评审 | **编辑回信** | 一叠便签从右缘依次飞入,自动贴到各段页边(气泡雨 = 便签雨) |
| 主对话(chat) | 信末**回执联** | 沿虚线撕下的写字条:写给"编者",agent 改动 = 换了新信纸 |
| comment.apply | 把便签上的建议**誊回信纸** | 人按采纳才誊;agent 永不直改(升权哲学不变) |

## 2. 展现层:3D 与动效(都是状态的语言,不是装饰)

1. **版本切换/回溯**:整叠信纸以 3D 扇形展开(fan);选中页被抽起(抬高 + 投影加深),翻折,压到叠顶;页角朱砂印清晰可见。失败/越界 = 该页抖一下不动。
2. **泡泡出现**:便签从右缘飞入(带 5–8° 旋转 + 弹簧过冲落定);未读便签呼吸发光(reduced-motion → 直接出现,遵守动效契约)。
3. **文字渐变**:段落入场 = 自下而上的晕染淡入 + 轻微上浮(6px);chat 改稿后,**变化段**先墨色晕染扩散再稳定(对应 change-flash 具名动效)。
4. **盖章**:印章抬起 → 砸落(180ms)→ 纸面微震(120ms)→ 印泥晕染开(一次,不循环)。
5. **镜头**:切换段落 = 轻推镜(对焦当前段);打开/收起便签 = 便签面拉出景深。全部走 `MotionPlayer` 具名动效 + 主题档位。

## 3. 主题映射(契约沿用,组件零分支)

信件模型是天然的换肤面——纸/印/字三件套:

| 主题 | 纸 | 印/签 | 气质 |
|---|---|---|---|
| classic | 米白档案纸 on 深色 | 蓝黑归档章 | 严肃工程 |
| **ink** | 宣纸 | **朱砂印 + 眉批**(本命主题) | 书房 |
| pixel | 锯齿边像素信纸 | 像素邮票 | 8-bit 邮箱 |
| moe | 奶油便签贴 | 爪印贴纸 | 软萌文具 |
| terminal | 针式打印纸(绿字) | 钢印 | 主机房 |
| blueprint | 描图纸(方格) | 图签章 | 工程图 |

token 落地:纸色 = `--bg-*` 反相档的主题档;印色 = `danger`(朱砂)/`warn`(便签);状态字 = 语义色双编码不变。**禁忌词纪律不变**:便签摘要层只说人话,技术原文进展开态。

## 4. 与内核的接点(只读视图层,零新通道)

- 信纸内容/版本/批注/回执 = 既有端点(`docs/*`、`comment`、`chat`、`review`、`apps/spawn` + action 管道)——与面板版同一数据源,两个视图可随时互换;
- 便签 = `chat-bubble` widget 的场景形态(state 同构;submit/apply/close 事件不变);
- 版本叠页 = `doc.rewind` 的唯一入口仍在管道;盖章动画由动作**成功**驱动,不做"先动画后失败";
- 寻址:`/root/doc-<name>/letter/para-<n>`、`…/note-<anchor>` —— 场景物件同样进 widget 树,agent 的 read/focus 可用。

## 5. 不做(v1)

- 不做多人协同/真实纸张物理模拟;不做 3D 里的长文排版(大段精读与编辑仍是 2D 面——信纸本身就是 2D 面,3D 负责空间与状态);
- 不做音效(沿用主题系统§6 政策);不做新卡型/新端点;
- DOM 版 `/platform/` 永久保留为无障碍/专家客户端(读屏、键盘全量在 DOM 侧)。

  (便签坞改走 hbox 流内定宽容器托管);

- **未做**:便签便签拖曳、多便签同开、版本叠键盘导航。

## 修订记录(v1.1,2026-08-17;功能形态裁决)

初版实现的两个形态错误,按用户裁决修订:

1. **批注内联化 + 纯用户批注**:页边折签/牵线全部撤掉——批注标记
   **内联跟在行文末尾**(`[注×N]` meta,点选开签);便签内容不是对话,
   是**用户自己的批注**——对齐后端 P2 annotations 模型(comment 对话链
   已退役:批注无即时 AI 回复,攒着等批处理;docs/PLAN-ANNOTATION-WORKFLOW-V2)。
   便签坞 = 引文 + 批注内容 + 状态章(pending/applied/ignored/outdated)+
   存/删;出海 = `POST /api/docs/{name}/annotations`(专属端点先例同 comment)。
2. **回溯不用小卡片**:版本叠扇形(卡片阵)撤掉,改为**时间卷轴**
   (VersionReel)——游戏式时间轴:拖动/滚轮 scrub、惯性滑动、吸附居中、
   ▼指针 + 选中放大,「盖印回溯」两段确认后走 doc.rewind 管道。
   轴上只有封存版;工作稿不在轴上(它就是"现在")。
3. 教训进测试:scene_smoke 13 项(内联标记存在性/批注坞预填/状态章/
   卷轴两击回调)全覆盖;旧 version_fan.gd 已删。
- **后端留口(如实)**:doc chat 端点的级联信封目前带的是 bubbles 旧流,
  annotations 是否进「按批注改」批处理链路,以后端 PLAN-ANNOTATION-WORKFLOW-V2
  的 generate 端点为准;本侧不新拉线。

## 修订记录(v1.3,2026-08-17;差异摘要化 + 缓存)

1. **diff 红绿行 → LLM 人话摘要**:回溯卷轴的背后提示,从原始差异行改为
   摘要助手(`skill.dev.doc_diff_summarizer`,tools=[] 白名单收口,只读 diff
   行)产出的一两句人话("标题改为…;新增两段…"这类)。
2. **缓存进 diffsum/**:`docs/<name>/diffsum/<from>__<to>.json`——版本不可变,
   版本对的摘要确定性,**缓存永不失效**;命中即回(cached 标记随行)。
   两版内容一致 → 不跑 LLM 直给并写缓存;LLM 故障 → 503,不写缓存。
3. **端点**:`GET /api/docs/{name}/diff-summary?from=vA&to=vB`(LLM 面,
   LLM_TIMEOUT 档;坏版本号 400 / 不存在 404 / 故障 503 与 review 同归类)。
4. **降级面**:摘要不可用时,客户端回落原始红绿行(读两版 + 行差集)——
   与全项目"LLM 不可用 → 回落规则"的先例一致。
5. pytest 新增 4 例(diffsum 缓存读写与校验 / API 命中缓存 / 一致免 LLM /
   LLM 故障 503 不写缓存),web_platform 123 全绿。

## 修订记录(v1.4,2026-08-17;「生成下一版」接进印钮栏)

1. **生成 = 批注批处理**(`POST /api/docs/{name}/generate`,P1/V2):
   全部 pending 批注 + 回执联上下文 → LLM 一次生成完整新稿 → **自动封存新版本**
   (meta 扩 generationInput/annotationResults)→ 批注逐条标 applied/ignored +
   aiNote → 重锚定(精确→±3 行模糊→outdated);版本冲突 409;解析不合重试
   一次再败 502,不半截落库。baseVersion 缺省 = 最新快照。
2. 印钮栏新增「生成」(快照与回溯之间):成功 → 盖章 + 新稿晕染 + 状态行报
   "已生成 vNNN · 采纳 N / 忽略 M"。client 增 `generate_doc`,app 增
   `generate_next`(失败空表 + 报告)。
3. 活体验证(godot.smoke.e2e):批注"把这段改写成更有信息量的两句话" →
   generate → **v008** 落叠,批注 applied,aiNote 说明改法;全文已换。
4. 两条生成路并存(设计如此):手动 = 回执联改 + 保存 + 快照;批处理 = 批注
   攒着 + 生成。前者是手上的事,后者是委托给编者。

## 修订记录(v1.8,2026-08-20;树状版本 + 版本页栈 + 版本树)

1. **树状版本模型**:历史对每个版本回推仍线性,但一个版本可衍生多条后继
   分支——回到旧版 → 写批注 → 再生成,新版挂在旧版下成新分支。后端:
   `doc_store.restore()` 记工作稿 `meta.baseVersion`;`snapshot()` 缺省
   parent = baseVersion(无则最新),封存后推进;generate 的 parent 同源。
   新增只读端点 `GET /api/docs/{name}/versions/tree`({base, versions:
   [{version,parent,at,source}]};路由必须声明在 `/versions/{version}`
   之前,否则 "tree" 被当版本号——实锤)。pytest web_platform 125 全绿。
2. **时间卷轴(VersionReel)与循环轨道(LoopTrack)退役**,顶栏改为:
   **版本页栈**(PageStack,≤20 版左新右旧部分重叠,悬停 = 翻书展开 +
   详情卡:时间/来源/对当前祖版的 LLM 摘要 + 「回到这版」两段确认)+
   右侧双主钮「再生成(N)」(pending=0 置灰)与「版本树」。
3. **版本树覆盖层**(VersionTree):parent 链分支图(depth 布局,同层排开),
   点节点 = 关层 + 页栈展开对应页;步进自适应(64–150px),首屏放不下时
   拖拽平移(技能树式,钳制区间恒含初始位,防拖丢也防 clamp min>max 报错)。
   另一实锤:容器对 visible=false 的子件不布局,open() 先亮层等两帧再建,
   否则 size=(0,0) 走兜底步进。
4. 生成阶段条退居顶栏下窄条;评审回印钮栏(保存/快照/评审/导出)。
   scene_smoke 32 全绿(页栈 6 断言 + 版本树节点断言);实拍:19 版文档
   首屏排开 17 版,余两版拖拽可达。
