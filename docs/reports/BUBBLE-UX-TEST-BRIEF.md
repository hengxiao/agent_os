# 批注批处理工作流 UX 验收测试任务书 v2(给 Kimi Desktop / WebBridge)

> 测试对象:Agent OS 文档编辑器的**批注批处理工作流**(批注卡 + 生成下一版本)
> 测试入口:`http://127.0.0.1:8391/platform/`(构建号见页角,应为 **2026-08-24.1**;不符先硬刷新 Ctrl+Shift+R)
> 测试方式:WebBridge 控制真实 Chrome,逐项操作 + 截图 + DOM/坐标取证
> 目的:v2 工作流(P1–P4)落地后的首轮外部验收——批注已从「泡内聊天室」改为
> 「单条批注卡」,AI 不再即时回复,批注攒着点「生成下一版本」批处理。
> **每条都要给出实际行为描述,不许只写"不对"**。

## 0. 前置准备

1. 打开 `http://127.0.0.1:8391/platform/`,确认页角构建号 = 2026-08-24.1;
2. 桌面点「对话」图标 → 输入框发「文档列表」→ 点卡片里的 `demo.test` → 文档窗口打开(左栏「对话 | 💬 批注」tab,右文档);
3. 以下测试均在右侧文档区进行。每个测试项:**操作 → 截图 → 记录实际行为 → 判 通过/偏离**。
4. 关键心智:**右键开的是批注输入框,不是聊天窗**;提交批注后**没有 AI 回复**——
   要等 E7/E8 点「🔄 生成下一版本」才有批处理结果。

## 1. 验收条目(每条 = 预期行为 + 取证要求)

**E1 右键开批注输入框**
操作:在文档某普通段落的**中段任意位置**右键(不选文字)。
预期:批注输入框在**右键点的旁边**浮出(不吸到行右缘、不在页顶);框内 =
textarea(占位文案)+ [取消][添加] 两钮;空内容时添加钮禁用。
取证:截图 + 输入框 `getBoundingClientRect` 与右键点坐标(左缘应在点击点 ±60px)。

**E2 选区高亮 + quote**
操作:拖选一句话中的**几个字**,保持选中,右键。
预期:输入框 quote 区显示选中的那几个字;提交后选中文字带**行内高亮**
(浅底);位置徽标带列范围(形如 `L3:C4-L3:C20`)。
取证:截图(高亮可见)+ 高亮元素 textContent 与选中文本逐字比对。

**E3 同一行两条批注**
操作:同一行的**两个不同位置**各右键一次,各提交一条批注。
预期:两条批注**各自独立**,行内有两个 💬 标记,各自在自己的位置附近。
取证:截图 + 两条批注的锚点串(应为两个不同的点锚点)。

**E4 点泡外 = 有内容提交 / 空取消**
操作 A:开一个批注框,输入几个字(不按 Enter),点击文档空白处。
预期 A:**自动提交**——输入框关闭,锚点旁出现 💬 标记(粉色边框 = pending)。
操作 B:再开一个**空**批注框,直接点文档空白处。
预期 B:**取消**——输入框关闭,不出现新标记。
取证:三张截图(A 输入中/A 提交后标记/B 取消后)。

**E5 悬停预览 tooltip**
操作:鼠标悬停在 E4A 的 💬 标记上(不点击),停 300ms。
预期:约 200ms 后浮出 tooltip 卡:批注内容摘录 + 锚点 + 相对时间;移开鼠标即消失。
取证:tooltip 截图 + 出现/消失两态。

**E6 展开 / 编辑 / 删除**
操作:点 E4A 的 💬 标记 → 批注卡展开(展示态:quote + 内容 + 状态徽标 +
[编辑]);点 [编辑] → 变输入态且草稿预填;改两个字提交;再点开卡头 🗑
(需点两下确认)删除;刷新页面。
预期:编辑提交后内容更新、状态回 pending(粉);删除后标记消失,
刷新后该批注**不再出现**。
取证:展开/编辑/删除三截图 + 刷新后状态。

**E7 生成钮四态**
操作:观察工具条「🔄 生成下一版本」:① 无待处理批注时;② 有 1 条 pending 时;
③ 点击生成后生成中;④(若遇到失败)失败后。
预期:① 禁用灰色;② 主色可点 + 计数徽标(1);③「⏳ 生成中…」不可点;
④「⚠ 生成失败,重试」红色。
取证:各态截图 + 按钮 disabled 属性实测。
(说明:无 pending 时可先删掉所有批注看 ①,再新建一条看 ②③。)

**E8 生成 → Diff 视图**
操作:有 pending 批注时点「生成下一版本」,等待(真 LLM 批处理,约 1–3 分钟)。
预期:自动切换到「📊 差异 vN→vN+1」视图:顶部标题带版本范围 + [✓ 采纳][↩ 回滚];
摘要卡(已应用/已忽略/部分 计数);每条来源批注卡(状态徽标 + 意见摘录 + AI 说明);
下方 unified diff 行(绿增红删);**批注标记变色**(粉 → 绿=已应用 / 灰=已忽略);
状态栏变为「vN+1 · N 条已应用 · …」。
取证:Diff 视图整屏截图 + 标记边框色 + 状态栏文案。
(注意:超时 3 分钟无结果 → 看按钮是否变红「重试」,如实记录为偏离并附控制台错误。)

**E9 采纳 / 回滚**
操作 A:E8 的 Diff 视图点「✓ 采纳」→ 回预览,版本号推进(vN+1)。
操作 B:再提交一条批注 → 再生成 → Diff 视图点「↩ 回滚」。
预期 B:文档内容**回到第二次生成前**;被回滚的版本**不删**(版本历史里标「已回滚」)。
取证:采纳后版本号 + 回滚前后文档文本比对 + 版本历史里的「已回滚 →vN」标记。

**E10 版本历史抽屉**
操作:点工具条 🕘(或状态栏版本号 / Ctrl+Shift+H)。
预期:右侧抽屉列出版本卡:当前版本(蓝点 +「当前」)、历史版本(○)、
已回滚(↩ 暗化);每卡 = 相对时间 + 差异统计(+a -b)+ 批注处理统计 +
操作钮([查看完整][查看差异][回滚到此前]);点「查看差异」→ 切到该版与父版的
只读 diff 视图(只有「回到当前」,无采纳/回滚);点「回滚到此前」→ 弹确认框列后果。
取证:抽屉截图 + 只读 diff 截图 + 确认框截图。

**E11 批注列表 tab**
操作:点左栏「💬 批注 (N)」tab。
预期:按状态分组(⏳ 待处理 / ✅ 已应用 / ❌ 已忽略 / ⚠ 已过时),组内按文档
位置排序;每行 = 内容摘录 + 锚点 + 时间 + 操作;点「定位」→ 滚动到标记并开卡;
「重新编辑」→ 输入态预填,提交回 pending;tab 标题 N = 待处理数。
取证:列表截图 + 定位开卡截图 + 重新编辑后状态。

## 3. 给测试执行者的备注

- **E8 是唯一依赖真 LLM 的条目**(生成约 1–3 分钟):等待期间按钮应是「⏳ 生成中…」;
  其余条目全是本地行为,秒级应有反馈;
- 提交批注后**没有 AI 回复是设计如此**(v2 工作流)——不要把「没有回复」记为偏离;
- 如果右键弹出了**浏览器默认菜单**而不是输入框,这本身就是重大发现,记录为 E1 偏离并截图;
- 每步操作之间留 300-500ms 间隔;所有截图存 workspace,文件名带条目号(如 `E1-open.png`);
- 测试数据随手清:测完把创建的批注用垃圾桶删掉(E9B 的回滚版本除外——版本不删),
  保持 demo.test 干净;
- 已知边界(不算偏离,别报):刷新后标记可能比批注晚一拍出现;行级锚点(无选区
  右键且 caret 映射失败时)quote 区显示整段摘录。
