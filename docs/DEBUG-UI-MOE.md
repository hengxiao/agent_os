# 萌系 Web 调试台 · 策划案

> 版本:v0.2(降格为主题目录的一员)
> 对象:Debugger P4 调试台(`#/debug`)的主题 `moe` 的详细规格
> 关系:**主题系统架构与主题目录见 `DEBUG-UI-THEMES.md`**;本文件只保留 moe 单主题的详细规格
> 基线:`WEB-UI.md` 定设计系统(= 内置主题 `classic`)

---

## 1. 概念定位

**一句话:调试 agent 像带一只精灵出门冒险——它跑你看,它停你问,它错你哄。**

现有调试台(P4)的信息架构是工程师视角:调用栈 / 轨迹 / 检视器三栏,控制条在上。
萌系版**不改这个 IA**,改的是"情绪层":

- 调试是个挫败感密集的活动(断点不命中、run 莫名挂掉、翻几百条消息找线索)。
  萌系表现层的价值不是"好看",是**把状态变化翻译成情绪反馈**,让开发者对
  run 的"健康状况"有直觉感知——就像 IDE 的绿色对勾让人安心。
- 同时它是一个**演示面**:Agent OS 的调试器能力(断点/单步/干预)本身是硬技术,
  萌系皮肤让它在分享截图、给非工程同事演示时更有记忆点。

### 设计原则(在 WEB-UI.md §2 四条之上追加两条)

5. **萌不压信**:萌化的是容器、动效、微文案;**技术内容一字不改**——错误 message、
   工具参数、帧 messages 永远原文呈现。用户信任建立在"这只精灵从不骗我"。
6. **萌可关闭**:`theme=classic|moe` 一键切换,状态同步进 URL(`#/debug/<sid>?theme=moe`);
   `prefers-reduced-motion` 下所有动效自动降级为静态。萌是选项,不是强加。

## 2. 核心创意:调试精灵(Mascot)

一只住在调试台里的圆团子精灵(名字待定,代号 **Mochi**),它是 run 的"化身":

| run/会话状态 | Mochi 表现 | 对应 token |
|---|---|---|
| 装配中/等待断点就绪 | 揉眼睛、打哈欠(刚被叫醒) | `--fg-2` |
| running | 原地小跑,呼吸浮动动画 | `--live` |
| paused(命中断点) | **立正+举爪**,眼睛瞪圆看着你("轮到你了!") | `--warn` |
| paused 超过 60s 无操作 | 坐下,托腮,冒泡泡("zzz…还继续吗") | `--warn` 降饱和 |
| step 单步 | 踮脚走一格,留下一个小爪印 | `--live` |
| modify/inject 干预 | 从背后掏出小纸条塞进去,假装没事发生 | — |
| error 断点命中 | 泪眼+耳朵耷拉,但举着错误卡片("这里疼…") | `--danger` |
| run done | 翻滚庆祝,撒花一次(不循环) | `--ok` |
| run aborted/stop | 鞠躬退场("先到这里喵") | `--aborted` |

- Mochi 住在**控制条右侧** + 暂停时**弹到轨迹中央暂停行旁边**(指向暂停点)。
- 形态:**纯 CSS/SVG**(圆团子+表情差分),不引入图片资源,保住"无构建、零依赖"非目标。
  表情差分 ≈ 8-10 个 SVG 变体,单文件 `<symbol>` 精灵表。

## 3. 视觉系统:Pastel Tokens(派生,不覆盖)

新文件 `css/tokens-moe.css`,**只定义 `--moe-*` 变量并映射到既有语义 token**;
`theme=moe` 时在 `<html>` 挂 `data-theme="moe"`,组件代码零改动(它们消费语义 token)。

```css
[data-theme="moe"] {
  /* 基底:奶油底,不是黑底——萌系暗色容易显脏 */
  --bg-0: #fdf6f0;  --bg-1: #fffaf5;  --bg-2: #ffeff0;  --bg-3: #ffe6ea;
  --line: #f2d8d5;
  --fg-0: #4a3f45;  --fg-1: #8a7580;  --fg-2: #b8a5ae;

  /* 语义色:pastel 化但保住色相锚点(绿=ok/黄=warn/红=danger/紫=aborted/蓝=live) */
  --ok:      #5ec9a7;
  --warn:    #f0b95e;
  --danger:  #f27070;
  --aborted: #b58ce8;
  --live:    #6db3f8;

  /* 萌系专属 */
  --moe-blush:   #ffd9e0;   /* 腮红/高亮 */
  --moe-paw:     #f7b8c4;   /* 爪印/断点 */
  --moe-cream:   #fff3d6;   /* 暂停行底色 */
  --moe-sky:     #d6ecff;   /* SSE live 呼吸 */

  /* 形状:圆角全面加大 */
  --r-sm: 8px; --r-md: 14px; --r-lg: 22px;
}
```

**可访问性红线**:pastel 语义色与 `--fg-0` 对比度必须 ≥ 4.5:1(WCAG AA),
上表初值需逐个实测微调;状态**永远颜色+图标/文字双编码**(继承基线原则,萌版不豁免)。

### 字体

```css
--font-ui: "Nunito", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif;
--font-mono: "SF Mono", "JetBrains Mono", Consolas, monospace;  /* 代码/参数区不动 */
```

Nunito 圆润但克制;**mono 字体不换**——代码和 JSON 是工作区,不萌化。
字体走系统回退链,不内嵌 webfont(零依赖);没有 Nunito 时落到系统圆体,可接受。

## 5. 交互与动效

只做**状态转移动效**,不做装饰性循环动画(省性能、不吵):

1. **命中断点**:Mochi 从控制条"跳"到暂停行(一次 300ms 位移),轨迹自动滚动到暂停行——
   位移方向即注意力引导,替代额外的"你停了"提示。
2. **step**:爪印从上一个停点"走"到新停点(两个爪印依次淡入),200ms。
3. **continue**:Mochi 冲刺回控制条,暂停行底色淡出。
4. **run done**:撒花一次(12 片花瓣,CSS transform,1s 后移除 DOM)——**不循环**。
5. **干预(modify/inject)**:小纸条飞入动画 250ms,然后控制条闪一下确认。

性能纪律:动效全部 `transform/opacity`(合成层),单帧 <16ms;SSE 高频事件
(流式 chunk)**不触发任何动效**;`prefers-reduced-motion` → 全部降级为即时切换。

## 6. 文案系统(微文案萌化,技术文本豁免)

| 场景 | classic | moe |
|---|---|---|
| 命中断点 | `paused @ pre:tool.call` | `抓到啦!停在 pre:tool.call`(状态原文并列保留) |
| 等待断点就绪 | `arming…` | `Mochi 准备出发…` |
| 空断点列表 | `no breakpoints` | `还没放捕兽夹哦` |
| 干预成功 | `patch applied` | `小纸条塞好啦` |
| run 失败 | `failed: <error>` | `呜…摔了一跤:<error 原文>` |
| stop | `aborted` | `先到这里喵(aborted)` |

规则:**状态原文/错误原文永远并列或可直接查看**(tooltip 或括号),萌化文案是"翻译层"不是"替换层"。

## 7. 实现路径(依附 P4,不单独排期)

萌系版**不是第二个页面**,是 P4 调试台的 `data-theme` 变体:

- **M1(随 P4 交付)**:`tokens-moe.css` + 主题切换开关(TopBar 🐾 按钮,localStorage 记忆 +
  URL 同步)+ Mochi 静态 SVG(3 个基础表情:running/paused/done)+ 贴纸化组件样式。
- **M2**:Mochi 表情差分全集(8-10 个)+ §5 的五组状态转移动效 + 爪印断点 gutter。
- **M3**:微文案全量替换(走 `i18n`-like 的文案表 `js/moe-copy.js`,classic/moe 两份)+
  彩蛋(连续 5 次 step 触发 Mochi 喘气:"慢点慢点")。
- 冒烟测试:`smoke-debug.test.mjs` 增加 `theme=moe` 用例——断言 token 映射生效、
  状态双编码(颜色+文字)在萌版下仍然成立、动效降级开关工作。**萌版不豁免可测试性。**

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 专业用户觉得幼稚,损害工具可信度 | 默认主题仍是 classic;萌系是显式切换的选项;技术内容零篡改 |
| pastel 下对比度不达标 | §3 红线逐个实测;不达标就加深 pastel(色相不动,降明度) |
| 动效拖慢 SSE 渲染 | 动效白名单制(§5 五组之外不加);高频事件不动效;reduced-motion 降级 |
| Mochi 形象沦为一次性噱头 | 它有信息职责(状态化身+注意力引导);若用户调研表明无感,M3 后停止投入,保留 M1 主题 |
| 维护两套 UI 漂移 | 不是两套:组件代码一份,差异全部收敛到 tokens + 文案表 + Mochi 层(可整体关闭) |

## 9. 不做(本期)

- 不做 Mochi 的 AI 对话能力(它不是另一个 agent,只是状态化身);
- 不做暗色萌系(暗色+pastel 易脏,先只做奶油底;有需求再议);
- 不做音效(浏览器自动播放策略+办公场景,收益低风险高);
- 不把萌系推广到 Runs/Skills/Tools 其他页面(只在调试台试点,验证后再说)。
